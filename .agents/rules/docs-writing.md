# Documentation Writing Guidelines (文件撰寫規範)

本專案的文件、程式碼註解與說明請遵循以下規範：

## 1. 語言與語氣 (Language & Tone)
- 主要說明文件（如 `README.md`）與專案註解一律優先使用**繁體中文（zh-TW）**。
- 語氣保持專業、簡潔、結構化且易於閱讀。

## 2. Markdown 格式規範 (Markdown Standard)
- **標題階層**：頁面僅保留一個一級標題 (`#`)，次級標題依序使用 `##`、`###`。
- **程式碼區塊**：所有程式碼與指令範例必須指定語言標籤（如 `bash`, `html`, `css`, `javascript`, `json`）。
- **清單與表格**：善用條列點與表格呈現比較或結構化資料，提昇可讀性。

## 3. 程式碼註解 (Code Documentation)
- **函式註解**：主要邏輯與 API 函式應包含簡短功能說明與參數註解。
- **關鍵邏輯說明**：針對非直覺或複雜的條件邏輯，註解應解釋「為什麼這樣做」而非僅重述「做了什麼」。

## 4. Commit Message 撰寫規範
- 使用語意化 Commit 格式：`<type>: <summary>`
  - `feat`: 新增/變更功能
  - `fix`: 修復已知問題
  - `docs`: 撰寫或更新文件
  - `style`: 樣式或排版微調
  - `refactor`: 程式碼重構（不改變對外行為）
